# Maintaining BELLA — rules for agents working on the system

Rules for any AI agent reading, writing, or building BELLA itself. These are not suggestions. Follow them, or the output is wrong.

BELLA is the design system for **ctrl_alt_design** (Elleta McDaniel's design engineering practice). It powers `elleta.design`, CHIP, and everything downstream. Its job is to keep that work editorial, deliberate, and recognizably not-AI-generic.

## Token-first, always

Never hard-code a hex value, an arbitrary pixel number, or a one-off font size. If the design calls for a color, spacing, radius, or type style, it resolves through a BELLA token. If the token you need doesn't exist yet, stop and ask — do not invent one inline and move on.

Reference tokens by path (`color.brand.ochre`, `spacing.4`, `typography.font-size.base`). Consuming apps read `tokens/bella.json` as the source of truth.

**Colour is authored twice, checked once (2026-10-05).** A colour primitive is hex in `$value` and OKLCH in `$extensions.bella.oklch`; ramps hold one hue. Change both together: the build fails when they drift by ΔE2000 1 or more. Never put an OKLCH value in `$value`, and never write a hex8 tint by hand when a relative colour of its base will do. See `docs/decisions/2026-10-05-oklch-primitives.md`.

## The accessibility bar (recorded 2026-07-21, Elleta; re-verified 2026-09-22)

**AAA-minded AA.** Concretely:

- **Aim for AAA wherever WCAG has an AAA level** (Elleta, 13 Nov: "i want to pass aaa on accesibilty to the solutions seems simple on all that stuff no"). So: text 7:1 (labels included, not only body), targets 44×44 (2.5.5), focus ring 3px outside the control (2.4.13), hover and focus content that stays while the pointer is on it (1.4.13), status that is never colour alone. Non-text contrast has no AAA level, so controls, outlines and marks stay at 3:1 on every surface. These are settled: agents apply them without asking her.

- **AAA for ink and body text, muted included (colour B, re-verified 2026-10-04).** Light: ink 15.05 on the ground (worst), 16.13 on card; muted `cool.600` `#474c5e` 7.95 on the ground, 7.34 on inset (worst). Dark: ink 16.26 on the ground, 12.35 on raised; muted `cool.300` `#b1b7c7` 9.41 on the ground, 7.15 on raised (worst). Body text never drops below AAA on any surface.
- **Ochre is a fill, never text on light (brand refresh, 2026-09-22).** `color.brand.ochre` `#e8a83e` carries ink `cool.900` `#1d2030` text (7.76:1) in both themes. On light it is never text or a hairline (2.08:1 on white, 1.94:1 on the ground); lines and the ring on light are `color.brand.ochre-deep` `#b97a14` (3.34:1 on the ground, 3.59:1 on card). On dark, ochre clears 6.90:1 even on raised.
- **The focus ring means focus only.** 3px, 3px offset, in `color.semantic.focus-ring` (its colour per theme lives in the semantic tokens). Never at rest, never as decoration.
- **Links are ink with an underline**; hover thickens the underline to 2px (`border.width.medium`). Ink holds AAA everywhere, so link and button labels are AAA.
- **The pairs are checked, not just recorded.** `scripts/contrast-pairs.mjs` (in the gate) computes every declared foreground/background pair in both themes, plus the forbidden pairs that must stay failing.
- **Every control outline is in the contrast gate** (Elleta, 12 Nov: "i thought we were accessibility first"; "Yes, fix both"). The secondary Button edge was 1.58:1 and slipped through because `scripts/contrast-pairs.mjs` did not list control outlines. Every control's outline (Button secondary, Input, Select, Combobox, FilterChip, SegmentedControl, Tabs) is a 3:1 pair in the gate, against every surface it sits on. A softer look never goes below 3:1.
- **Controls clear 3:1, hairlines are decoration.** `border-strong` (`cool.500` `#686d7d` light, `cool.400` `#858b9f` dark; one step each, Elleta, 2026-10-04) is the input and control border, 3:1 on every surface: light 4.44 on inset (worst), 5.16 on card; dark 4.23 on raised (worst), 4.76 on inset, 5.13 on card. The hairline (`border` `cool.100` / `cool.800`, `border-subtle` and `border-faint` `cool.50` / `cool.850`) is decorative only and never marks a control.
- **Worst-ground-wins.** A text token passes on the *worst* surface it is allowed to sit on, or its usage metadata forbids that surface. Verified ratios are recorded per token in `$extensions.bella.a11y`, dated.

## Typography minimums

These are floors, not defaults. Going below is a bug. The values live in the type tokens (`tokens/primitive.json` → `typography.font-size`); this section only states the floor.

- **The floor is `font-size.tag`:** "Floor for tags and small labels. Never go smaller." `font-size.base` adds: "Non-negotiable minimum for reading text in BELLA is 16px."
- **Reading text** is `font-size.body`, in `text-body`, never grey. The `chip` theme sets `font-size.body` to the floor (the app's density); no theme goes under it.
- **The one recorded exception is a hard limit, not a size:** `font-size.tag` and `font-size.mono` both list "Never below 13px" in their `dont`. No token sits between 13 and 16, so 13 to 14px fine print has no token and is off-system: use `font-size.tag`.
- Labels and meta are sentence case, no tracking.

## Surface behavior

- Cards: `surface-card` fill, 1px `border-faint`, `radius.card` (16px), `shadow.card` at rest (Elleta, 2026-10-04; Peek stays flat), no accent-tinted border, no gradient or scrim over media. Only interactive cards (one link or one button) respond: on hover and focus-visible, `motion.transform.hover-lift` (`translateY(-2px)`) plus `shadow.hover`, over `motion.duration.lift` (200ms). No lift under reduced motion. A static card keeps its rest shadow and never changes on hover. The lift is the tell: it marks what you can click.
- Buttons: the contract wins, `tokens/component.json` → `component.button` (a flat primary plate, no gloss, no edge, never lifts; sentence case; sizes default and `sm`). Lift is reserved for cards. No trace ring on buttons; the only ring is focus. The primary contact CTA reads "Let's talk".
- One light source, upper-left: highlights top-left, shadows down-right (orbs). The elevation tokens (`shadow.orb*`, `shadow.key-*`, `shadow.switch-*`) are a token lock for the existing components: do not flatten; the depth IS the system. **The new patterns (diagrams, steps, eyebrows, callouts) carry no shadow**: 1px ink strokes and hairlines only.
- Hover transitions are quick (≤250ms) and eased. No bouncing, no spring physics.
- **Diagram motion** (style unify, 2026-09-22): `motion.duration.draw` + `motion.easing.draw` for lines, `motion.duration.pop` + `motion.easing.pop` for elements appearing, `motion.stagger.min`–`max` between steps. Plays once when in view, then holds still; reduced motion shows the finished frame. The pop overshoot is for play-once reveals only, never hover or state changes.

## Actions in a view (layout foundation, 2026-10-03, Elleta)

One style per job, so a page never mixes button looks for the same kind of action:

- **Main action:** at most ONE Button `primary` (sentence case: "Save changes", never "SAVE CHANGES"; Elleta, 2026-10-05) per view, and only for the action the view exists for. Zero is fine. A primary shown as a specimen (Atlas, Storybook) is content, not an action.
- **Secondary actions:** Button `secondary`.
- **Small inline actions** (on a tile, under an answer, in a list row, "Test", "Copy"): ActionChip, sentence case.
- **Navigation** (going somewhere else): Link, or NavList in a sidebar. Not a Button and not an ActionChip.
- **Filters, toggles, sort, picking a view:** FilterChip, SegmentedControl, Select. Never a Button.
- No locally styled `<button>` in a consuming app: if none of these fits, ask before inventing one.

## Layout rules for consumers (from RULES.md v0.2, folded 12 Nov 2026)

- **Text on a fixed dark block inside a light page** uses `--ink-on-dark-strong`, `-body`, `-muted`: they do not flip with the theme, so a dark footer keeps light ink in both modes.
- **Sibling cards share one height:** the grid `align-items: stretch`, the card `height: 100%` and a flex column, its body `flex: 1`. Never `min-height` in px on a card with variable content.
- **Card copy never truncates** (no ellipsis, no line clamp) unless the card opts in with `Card--truncate`, for listing UIs only. Shorten the copy instead.
- **Sticky headers:** set `--header-height` at `:root`, `scroll-padding-top: calc(var(--header-height) + var(--spacing-4))` on `html` and the content wrapper, and the same value as `scroll-margin-top` on anchor targets.
- **Card grids** use `repeat(auto-fill, minmax(var(--card-min), 1fr))`; a fixed `repeat(N, 1fr)` only when there are exactly N items, always. No centred widow.
- **Focus:** `outline: var(--ring-focus-width) solid var(--ring-focus-color); outline-offset: var(--ring-focus-offset)`. `outline: none` only with an equal visible replacement.
- Legacy code that breaks a rule is migrated, not grandfathered. If a rule conflicts with a comp, escalate the comp, not the rule.

## Aesthetic stance

Editorial. Confident. Closer to a magazine or a well-set book than a SaaS dashboard. Avoid:

- Gradient-on-gradient hero blobs
- Generic rounded-everything, pastel-everything, emoji-in-every-heading "friendly AI" UI
- Stock iconography where typography would do
- Centred text everywhere: reading text is left-aligned, and asymmetric layouts are fine. (This is about text alignment. A picture or block still sits centred in its frame or panel.)

When in doubt, the answer is more type, less chrome.

- **Colour:** reading text is `text-body`, never grey; `text-secondary` is for non-reading UI only (icons, placeholders).
- **Buttons:** tiers, sizes (default and `sm`) and the 44px tap area live in `component.button`.

ELLETA for the site, BELLA for the system. Never below 32px tall, never recoloured, never body type or a heading. `typography.font-family.wordmark` (Unique) remains for legacy consumers only.

**Icons — one set, declared (2026-07-22):** Iconoir (MIT, the portfolio's set) is BELLA's only icon source. Every glyph lives in the Icon registry (`src/components/Icon/registry.ts`) and renders through the Icon component: icon-ramp sizes, always currentColor, decorative by default. No mixing sets, no one-off inline SVGs anywhere; a meaningful icon requires a label and never stands without text unless its accessible name is proven in a Behavior story. audit:quality fails any inline `<svg>` outside the Icon component. **The one named exception (2026-09-22): diagram patterns** — FlowDiagram, ProcessSteps and case-study diagrams under `src/patterns/Diagrams/` — draw their own SVG, marked `data-bella-diagram`; 1px ink strokes and chip fills only, `role="img"` with an aria-label that tells the story. **The second named exception (brand refresh): brand art** — BrandWordmark and PatternField, marked `data-bella-brand`: a labelled image (`role="img"` + the word) or aria-hidden decoration, nothing in between.

Any value you see as `"TBD"` in the token JSON is a genuine unknown — stop and ask. Do not fill it in.

## Reading and layout (Elleta's repeated asks, written down 12 Nov 2026)

She asked for each of these many times; they apply to every screen, page and doc.
- **Readable:** reading text 16px or more, line height 1.5 or more, 45–75 characters per line, left-aligned. If words look like they run together, it fails.
- **Hierarchy:** three text levels per block (title, subtitle, meta), each with its own token, and the title is the biggest. Never two levels at the same size.
- **One pattern per job:** one style each for titles, type, tables, radius and hover across a product. Compare with a finished page before calling anything done.
- **Few actions:** one primary per view, at most two actions per card (bottom right), separators only between groups, no card inside a card (a white specimen card on a doc stage is one level and is fine).
- **One table style:** DataTable with row highlight. It becomes a list below 1024 or inside a drawer.
- **An icon inside a control takes the control's text colour** (Elleta, 12 Nov: "why is the icon a diff color"). The icon uses the same variable as the control's label in every variant and state (Button: primary's foreground, secondary's text-accent, tertiary's link and link-hover, disabled's text-muted), never the Icon's own default. It sits inside the label roll so it moves with the text.
- **Contrast shown:** every new colour pair appears with its measured ratio and the rule for its use.

## Doc pages (Figma and site, Elleta, 12 Nov 2026)

A picture is worth a thousand words. Every BELLA doc page, foundation or component, is built this way:
- **One check, must pass before she sees anything** (Elleta, 12 Nov: "Yes, make it"; "this is infuritating can we just work like we are meant to it never changes"). Every Figma build ends by running `scripts/figma-doc-check.js` on the frame it touched (Desktop Bridge `figma_execute`, `CHECK_OPTS` first: fileKey, target, approved ids; `descriptions: true` in BellaComponents). It checks approved frames, style overrides, code colours and contrast, pin numbers and leaders, overlaps and fill, the 16px floor and 1.5 line height, raw colours, and the description pattern. `pass: false` means not done: fix and re-run. The rules below say why each check exists; the script is how they are checked. A miss a reviewer finds twice becomes an assertion in the script the same night (12 Nov night: builders reported pin order, leader ends and row heights fixed three times when they weren't); a builder's "fixed" counts only when the check proves it. A check that skips a part (e.g. paint, which holds the code colours) does not count: 13 Nov, a "reduced check" passed while two code blocks had lost every syntax colour.
- **Brand intro is a hero, like elleta.design's** (Elleta, 12 Nov: "i want it to look professibla nd high fidelity maybe we can use the updated dashboard designs", "something more like the hero on my site"). The top of the Brand page (and Storybook's Welcome) is one composed hero, not a mosaic of tiles: a big Newsreader title with a logo mark as its full stop, one short line, then real CHIP v3 screens with floating BELLA token cards, pins and leaders to token chips, and a measured selection frame, at 2x and pixel-aligned. This is the one place where layered cards with BELLA shadows and the logo's four mark colours on pins are allowed; every other doc section keeps one card level and pink-only measuring.
- **Doc pages are built from Docs Kit components** (Elleta, 12 Nov: "wait is the component template not a component ?' then the changes will go out in bulk no??", "Yes, make components"). Section, Specimen, Measure tag, State row, Do/Don't pair, When-to-use card, Contrast row and block, Accessibility block and Properties row are Docs Kit components with slots; pages place instances, never drawn copies, so one change updates every page on publish. The whole page is one "Component doc page" component too (Elleta, 12 Nov: "i would make a whole page with bits because im getting tired of fixing each one individually"): header and the sections in order, each with a content slot, so every doc page is an instance and a fix is made once. Layout follows the rated Figma template (see "The rated Figma template is the doc page model"); the code is the source only for behaviour wording and measured values (Elleta, 12 Nov: "wait why storybook i thought we were making the component template"). Amend what exists before building new (Elleta, 12 Nov: "idon tthink you need to rebuild all the compoents we have some like the page card.. just check what we have what needs to be amended and fixed no??"): start from the Docs Kit's existing components (Page card, Section, Do / Don't card, A11y note, Table row, CodeBlock…), list what each needs to build the rated template, and fix those; a new component only where nothing does the job.
- **White page, stone stage** (Elleta, 12 Nov, picked B: "its still flat"). The doc page is white (`surface`). Each section's picture sits on a recessed stage filled with warm stone, `color/semantic/surface-stage` (stone.95 #F0EEEB; Elleta, 12 Nov: "Add stage token"; until it is published, the primitive `color/stone/95`), not `color/semantic/background` (stone.97, too faint on white), never the cool `surface-inset` (Elleta, 12 Nov: "i thought we were doing a stone bg on the cards"). Grid lines in warm `stone/92` (#E6E4E1; `border-subtle` is cool, and she approved the stone sample with this grid, 12 Nov), hairline in `border`, so the content reads against the page. No shadow on stages. On the stage, each specimen sits on its own white card, an instance of BELLA's Card from BellaComponents, never a drawn frame (Elleta, 12 Nov: "can we use the card we have in the component library for this"), with its label and one line on the stone below it, as on the Brand page's "The marks" (Elleta, 12 Nov: "the content has a card inside to make it pop more"). One card level only, never a card inside a card.
- **Every section sits in its frame, centred** (Elleta, 12 Nov: "its missing its frame and its not centered"). Heading and one line above, then the picture inside the white panel on the light grid, with the content centred in the panel, never pinned to its left edge. No section without its panel.
- **Pictures first.** Each section is a heading, one plain line, then a picture that explains the token or component on its own: real specimens, pins and leaders, brackets, measured tags. Tables only where a picture can't carry the fact.
- **Links in Figma are Figma-native** (Elleta, 12 Nov). Figma allows one documentation link per component: it is Storybook, and it shows in Dev Mode and the Assets panel. The GitHub link is the last line of the component description. The page header keeps one row of real text links (icon and word as one link). There is no Source section at the bottom.
- **Done means passing and seen clean** (13 Nov, after pages that passed the check showed clipped chip text, a pin over text and "Compone nts" broken mid-word; Elleta: "Never say fixed until you've looked"). A doc page counts as done only when `figma-doc-check.js` passes AND its 100% export shows no fault anyone has named. Reports count "done" and "passes, has faults" separately. The 100% look that makes a page "done" is a fresh agent's, never the builder's (13 Nov: three pages a builder called done had leftover "Design systems" text, leaders on the wrong spot and a key cap that never showed). Every visible fault a person finds becomes a check assertion the same day (clipped text in chips and rows, a word broken mid-word, a pin over text, a leader that can't reach its part).
- **Doc pages ship at 5/5 reader clarity** (Elleta, 12 Nov: "i want 5 out of 5"). Every section is rated 1 to 5 by a fresh agent (interface-critique: can a first-time reader say what it tells them without its caption?). Below 5 gets fixed and re-rated; after two rounds still below 5, stop and show her why with options. The rating table goes in front of the screenshots.
- **One job per section** (Elleta, 12 Nov: "is it meant to be anatomy?? not overview.. i think we are lost"). Overview = the live component, simply, nothing measured. Anatomy = the parts, numbered (CHIP's "On the stage" look). States = the state thumbnails. Accessibility = every measured number, pass or fail. Never put a measurement or a failure in the Overview, and never merge two sections' jobs into one picture.
- **Component pages also show** (Elleta, 12 Nov): When to use / instead use (the right choice next to the near-miss), Sizes (every size side by side with the 44px target bracketed), and Behaviour and motion (before/after frames with duration and easing). Each is a heading, one line and a picture.
- **Little text is part of the brand** (Elleta, 12 Nov: "part of the brand is not so much text"). Not only a doc-page rule: covers, the Brand page, Figma descriptions, CHIP screens. If a picture can say it, cut the words.
- **No text walls.** No paragraph over one line, apart from the header lead (two lines at most). Leads are plain and useful: no puns or jokey lines.
- **No gimmicks.** No tilted or decorative pieces, no hero that repeats a section. Joy comes from big, real specimens, BELLA's colours (light washes for large blocks) and space.

## Tiered inheritance

Repos that install BELLA as a `devDependency` inherit this AGENTS.md automatically. They may add their own `AGENTS.md` at their root to layer additional rules — but downstream rules only *extend* or *tighten* BELLA's. They do not relax them. A consuming repo cannot, for example, use pure white off the page ground, drop body text to 14px, put colour in a stroke outside focus and status, set ochre as text on light, or set any text below 16px.

If a consuming repo's rules conflict with BELLA's, BELLA wins. Flag the conflict; don't silently resolve it.

## Data marks (2026-10-03, Elleta)

Data marks (sparklines, charts) may use inline SVG, marked `data-bella-diagram`, and must carry an accessible text equivalent: `role="img"` with an `aria-label` that says what the mark shows (Stat's sparkline: "Stories: 18 to 22 over 22 syncs"). Same drawing rules as diagrams: ink strokes, chip fills, no state colour.
