# BELLA

BELLA is the design system for ctrl_alt_design, Elleta McDaniel's design
engineering practice. It powers [elleta.design](https://elleta.design), CHIP,
and everything downstream. This Storybook is BELLA's documentation site: the
same pattern Polaris and Carbon use, where the docs render from the shipped
code and cannot drift from it.

## What it is

- **Token-first.** Every colour, spacing step, radius, and type style resolves
  through a DTCG token. Consumers read `tokens/bella.css` and `tokens/bella.json`
  as the source of truth. Nothing is hard-coded, including this Storybook's own
  chrome, which is generated from the token build.
- **Accessibility-first.** The bar is AAA-minded AA, recorded per token as
  verified, dated contrast ratios. See the
  [Accessibility](?path=/docs/foundations-accessibility--docs) page.
- **Agent-readable.** `AGENTS.md` states the rules for any AI tool that reads,
  writes, or consumes BELLA. The token metadata carries usage constraints, so
  the system explains itself to tools as well as people.

## The lush identity

Two inks, one accent, two faces. Light mode sits ink `color.brand.ink` on warm
off-white ground `color.brand.ground`; dark mode is navy `color.brand.navy`,
not black. The single accent theme-flips: iris in light, periwinkle in dark,
never both, never paired with a second accent. Type is Unique (display, 700
only, 24px and up) and Geist (everything else). Pure white is banned as a
solid fill; surfaces separate by lift and shadow, not darkness.

The stance is editorial: closer to a magazine or a well-set book than a SaaS
dashboard. When in doubt, more type, less chrome.

## Agent access

In dev mode this Storybook serves an MCP endpoint at `/mcp`
(`@storybook/addon-mcp`), so AI tools query the stories and docs the same way
people browse them. Setup and the tool list are in
[Getting Started](?path=/docs/getting-started--docs).
