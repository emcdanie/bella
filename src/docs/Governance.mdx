## The gate

`npm run gate` is the ship check, and CI runs it on every PR and every push to
main. Green or it isn't done: there is no partial pass and no per-check
opt-out.

Every audit, what it asserts, why it exists, where it runs, and the one dated
allowlist are on [Governance / The Gate](?path=/docs/governance-the-gate--docs).

## The change flow

Agents (AI sessions, including the one that wrote this page) work on
short-lived branches and open PRs. Agents never merge. Elleta reviews and
merges every change, on green, and stops at recorded checkpoints for
anything visual or content-shaped. That is the trust level, stated plainly:
agents propose, one human disposes.

## Escalation levels

Work runs at one of three levels, set per task by Elleta:

- **STRICT** is the default. The agent changes exactly what the task names.
  Anything ambiguous, out of scope, or missing (a token that does not exist,
  a value marked TBD) stops the work with a question rather than a guess.
- **FLAG** lets the agent proceed through judgment calls, but every one of
  them is surfaced in the report and the PR. Nothing is silently resolved.
- **BUILD** grants creative latitude inside stated bounds: new files, new
  pages, proposed tokens. The PR flow and the gate still apply in full.

No level allows merging, force-pushing, or relaxing a recorded rule.

## Component extraction

Components move up from the reference consumer one at a time, worst offenders
first, and the consumer deletes its local copy in the same commit. The full
definition of done, the copy-sync model, and how a fix travels back upstream
are on
[Governance / Contribution & Tiers](?path=/docs/governance-contribution-tiers--docs).

## Decision records

Decisions are recorded where they bind, with dates:

- **The accessibility bar** is rule 9 in `docs/RULES.md` (AAA-minded AA,
  recorded 2026-07-21), with verified ratios written into each token's
  metadata. See [Accessibility](?path=/docs/foundations-accessibility--docs).
- **Recorded divergences** are written next to the thing that diverges: the
  Card `peek` variant as the one fixed-context surface, the keycap logo as
  the one sub-24px Unique, the carried status colours as non-text roles
  pending a BELLA-native status ladder. A divergence without a written
  record is a bug.

Rules version forward only: future rule sets may add rules, never relax
them. Downstream consumers may tighten BELLA's rules and never loosen them.

## Versioning

Semver against the token contract, tagged `vX.Y.Z-bella`. Every release gets
a [Changelog](?path=/docs/changelog--docs) entry; the
Changelog page renders `CHANGELOG.md` directly, so the site and the file
cannot disagree.

## Page anatomy

Every doc page here follows one shape: an H1, a one-paragraph standfirst,
then sections. Component autodocs pages carry, in order: the component
description verbatim from the committed source, the live primary story, the
props table, the tokens the component consumes, and its accessibility notes.
