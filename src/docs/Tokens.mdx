  BELLA is token-first: if a value is not a token, it does not exist. The
  tokens are DTCG format JSON, structured for Tokens Studio, and every
  downstream artifact is generated from them.

## Tiers

Token values come from Figma Foundations, exported as DTCG JSON into
`tokens/figma/`. Four modes: BELLA light, BELLA dark, Chip light, Chip dark.

1. **Tier 1** (`tokens/figma/primitive.json`): ramps and scales, named by hue
   and step or by value. The same in every mode. Parts never read these.
2. **Tier 2** (`tokens/figma/semantic/<mode>.json`): shared meaning, in
   groups: `color/background`, `color/border`, `color/content` and their
   utility groups, plus type and focus ring. A theme is a remap of Tier 2.
3. **Tier 3** (`tokens/figma/component/<mode>.json`): a part's own token,
   only where a part must differ between modes.

Screen sizes live in `tokens/figma/breakpoints/` (large, small, chip). Part
contracts (props, variants, a11y notes) live in `tokens/contracts.json`.

## Build pipeline

`npm run build` runs `tokens/build.mjs` (Style Dictionary), which reads the
export and emits everything else:

| Artifact                          | Job                                              |
| --------------------------------- | ------------------------------------------------ |
| `tokens/bella.css`                | CSS custom properties: `:root` is BELLA light; `[data-theme="bella-dark"]`, `"chip-light"`, `"chip-dark"`; small-screen sizes under one media query |
| `tokens/bella.json`               | Every token per theme: value, alias, type, description, CSS name |
| `docs/bella.css`, `docs/tokens.md`| Copies and reference table for the GH Pages site |
| `.storybook/theme-values.json`    | This Storybook's manager theme values            |

The CSS name of a token is its Figma code syntax (WEB): the path joined with
`-`. The build fails if Figma's field ever disagrees.

Generated files are never edited by hand. That includes this Storybook's own
branding: the manager chrome reads `theme-values.json`, so the doc site cannot
carry a hex the tokens do not.

## The drift gate

CI rebuilds the tokens on every push and fails if any generated artifact
differs from what is committed. Locally, `npm run gate` runs the same build
and diff, then the full visual audit (`audit:visual`: every story, both
themes, axe plus interaction tests plus image snapshots). A token change that
skips the build, or a hand-edit to a generated file, cannot reach main.

The [Foundations](?path=/docs/foundations-colors--docs) pages render swatches,
ramps, and scales from `bella.json` at build time; like the contrast table,
they are views of the source, not copies of it.
